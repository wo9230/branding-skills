# Security Policy

## Reporting

Use the repository's private vulnerability reporting feature when available. Include only the affected file, line, behavior, and a minimal reproduction. Do not place sensitive values or private records in a public issue.

## Repository rules

- Keep credentials and authentication artifacts outside the repository.
- Use synthetic fixtures for examples and tests.
- Review staged changes before every commit.
- Run the repository verification and credential scanners before a release.
- Treat automated results as bounded evidence, not a guarantee.
