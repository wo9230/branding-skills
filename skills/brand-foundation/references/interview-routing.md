# 动态访谈与停止规则

问题用于解决决策缺口，不用于走完问卷。先从材料中提取答案，再问用户本人才能回答且会改变当前交付物的内容。

## 缺口队列

排除已经回答、换词重复、只能通过研究回答、只影响后续阶段或不会改变当前选择的问题。剩余缺口按以下顺序处理：

1. 权限、隐私与品牌对象；
2. 来源冲突与高风险主张；
3. 实际供给、优先受众与触发任务；
4. 战略取舍、承诺和商业去向；
5. 真实事件、声音样本与执行约束；
6. 只影响表达偏好的事项。

抽象回答先追一个具体事件、动作或记录。用户说“不知道”时记录 `unknown`、影响和验证办法，然后继续。

## 两种节奏

### `focused`

用户要求苏格拉底拷问、逐问或需要处理敏感冲突时使用。每轮只问一个原子问题；一个问题只索取一个事实或一个决定。不得用“以及、分别、同时”或括号清单藏入多问。

### `batch`

用户要求加快速度、一次多问或希望集中填写时使用。每批通常覆盖一个决策层，给出 6–12 个编号问题；问题可以来自多个家族，但每一题仍然原子化。优先把相互依赖的问题放在同一批，允许用户跳题、合并回答或写“不知道”。收到回答后先提取和去重，再发下一批，不能机械重复整套问题。

默认沿用用户刚明确选择的节奏。没有明确偏好时，敏感或高冲突任务用 `focused`，普通建档用一个短批次开始。

## 问题家族

| 家族 | 要确定什么 | 问法方向 |
|---|---|---|
| 范围 | 品牌对象、急需产物、用途、审批人 | 这次哪份实际内容最急着使用？ |
| 当前现实 | 已存在的产品、服务、交付和阶段 | 对方现在能从你这里实际拿到什么？ |
| 目标 | 当前周期最重要的变化和不追目标 | 未来 90 天只允许一个主要结果，会选什么？ |
| 适配边界 | 谁适合、谁不适合、必要条件 | 什么条件出现时你会建议对方别买？ |
| 触发任务 | 具体事件、约束和失败尝试 | 最近一次需求出现前发生了什么？ |
| 替代取舍 | 对方原来的办法与其优势 | 对方原来怎样完成？那个办法好在哪里？ |
| 价值 | 当下收获、持续价值和行动 | 对方这次和持续一段时间分别得到什么？ |
| 商业去向 | 供给、价格带、购买路径或长期用途 | 品牌最终希望合适的人完成哪个业务动作？ |
| 证据限制 | 支持承诺的记录和不能保证什么 | 哪份记录支持这句话，适用范围是什么？ |
| 身份观点 | 由行为和事件体现的原则 | 最近一次为坚持原则做了什么取舍？ |
| 声音 | 真实样本、作者、编辑链和禁用表达 | 哪份内容最像希望保留的表达？ |
| 执行 | 时间、人力、渠道和维护能力 | 哪项现实约束最可能让方案无法持续？ |
| 变化 | 旧版保留、停止与改变 | 哪条旧结论已经失效，依据是什么？ |

个人 IP 建档时应覆盖目标、证据、受众、价值、业务和执行六个诊断面，但不要求按固定顺序或一次填满。

## 停止状态

- `READY`：另一位合格执行者可在声明范围内继续，无需自创品牌对象、供给、受众、承诺、证据或经营决定。
- `PARTIAL`：用户暂停或先看草案；输出 `V0.x` 并保留下一项决定。
- `RESEARCH-GAP`：当前结论依赖外部证据，继续问用户不能解决。
- `BLOCKED`：归属、权限或关键冲突没有可决策的人。
- `DEFERRED`：剩余未知不阻塞当前交付。

不要按回答数量判断完成。每次批次或模块结束时，只复述：材料支持的现实、用户刚批准的选择、AI 候选、仍未知或需研究的事项。不得把复述中的推断写成用户自述。

中断时在 `BRAND.md` 保存当前目标、节奏、状态、已读材料、最新决定、最高优先级缺口和下一题/下一批主题，不依赖聊天记忆续接。
