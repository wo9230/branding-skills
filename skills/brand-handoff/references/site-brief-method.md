# 建站交接：从定位到页面

`SITE-BRIEF.md` 告诉建站的人或建站 AI：网站要完成什么、有哪些页面、每页说什么、放哪些证明。它到"页面结构和每页说什么"为止：不生成代码，不绑定任何建站技术，不做视觉设计。

## 什么时候生成

- 只在做了建站模块时生成：`PROGRESS.md` 的 `modules` 含 `website`，并且 W1 已经完成。W1 没完成时，先回 `$brand-journey` 把它做完。
- 没有 `PROGRESS.md`（单独使用本技能）时，用户明确要求才生成，并且 `BRAND.md` 里要有网站的任务和主转化动作。缺这两项，就回 `$brand-foundation` 或 `$brand-journey` 补上，不自己定。
- 生成前问一次是否写文件。

## 输入

| 输入 | 用来做什么 | 没有时 |
|---|---|---|
| `BRAND.md` | 定位、优先客户、替代方案、证明、禁止的主张、`DEC-SITE` | 不能生成 |
| `MESSAGING.md` | 页面文案，按 Copy ID 引用 | 只用 `BRAND.md` 里已批准的最小信息；其余文案位置写"待表达" |
| `output/DESIGN.md` | 视觉规范 | 不引用；在第 9 节写明还没有视觉规范 |
| 细分包的"网站交接模式" | 网站类型、主转化、常见页面 | 用下面的通用默认模式 |

细分包怎样取：从 `BRAND.md` 文件头读 `segment`；能读到 `$brand-journey` 的 `references/segments/<segment>.md`，就用它的第 6 节"网站交接模式"；读不到，或 `segment` 是 `generic`、`unknown`，就用通用默认模式。

## 推导方法

1. **先定任务**。网站只有一个主要任务和一个主转化动作，来自 `DEC-SITE`。次要动作最多两个。
2. **再定谁来、带着什么问题来**。从优先客户和触发场景，推出访客到站时最想确认的三到五个问题；从渠道决策（没做落地模块时用 W1 里"访客从哪里来"的回答），推出他们先落在哪一页。
3. **每页回答一个问题**。页面内容的顺序是：访客的问题、主信息、证明、行动。一页只推一个主要行动。
4. **证明跟着说法走**。页面上每个承重的说法旁边放对应的证明。没有可公开证明的说法不上页面，或降成不带承诺的表述。
5. **最后查缺口**。素材、文案、证明各缺什么，列进第 7 节。不用占位内容冒充。

## 九节各写什么

| 小节 | 写什么 |
|---|---|
| `## 1. 网站的任务` | 唯一主要任务、主转化动作、次要动作、访客主要从哪些渠道来，各带 Decision ID |
| `## 2. 站点结构` | 页面树、导航顺序、网址命名（用网站语言，小写加连字符） |
| `## 3. 逐页简报` | 每页一小段：目的；回答访客的哪个问题；主信息（引用 Copy ID）；区块顺序；要放的证明（Claim ID 和放行状态）；行动按钮；所需素材（已有或缺失） |
| `## 4. 转化路径` | 询盘表单字段、下单流程要点或其他联系方式；提交之后发生什么；线索由谁、多久之内跟进 |
| `## 5. 搜索与内容主题` | 来自客户原话和访谈的主题词，标为 `[假设]` |
| `## 6. 语言与本地化` | 网站语言、主语言、各语言覆盖哪些页面；访谈语言与网站语言不同时由谁确认译稿；单位、币种、联系方式的写法 |
| `## 7. 素材清单与缺口` | 照片、视频、证书、案例文件；各自已有还是缺失；使用权限 |
| `## 8. 放行检查` | 可以公开出现的说法；只能内部使用的说法；绝对不能出现的说法 |
| `## 9. 给建站 AI 的要求` | 必须做的和不能做的 |

第 9 节至少写这几条：只用第 3 节引用的文案和证明；不新增承诺、数字、客户名称或评价；缺素材的地方留空并标注，不用没有授权的图片；视觉以 `output/DESIGN.md` 为准（存在时）；标着"概念，未批准"时只做草稿，不发布。

## 规则

- 不生成代码，不指定框架、主题或插件。`platform` 只记客户已经定下的平台限制。
- 页面上每句承重的文案，都要能追到 Copy ID、Claim ID 或 Decision ID。没有 `MESSAGING.md` 时，文案位置写"待表达"，并指向它依据的 Decision ID。
- `brief_status` 怎样定：

  | 取值 | 条件 |
  |---|---|
  | `concept` | 主线的关卡（阶段 4 或阶段 7）没过，或依据的定位仍是候选 |
  | `working` | 关卡已过，但有页面依据的文案或决策还是候选 |
  | `approved` | 全部依据都已批准，并有具名审批人对本交接文件的确认 |

  `concept` 时，标题下第一行写：`> **概念，未批准**`。
- 没放行的说法不进第 3 节的页面内容，只列在第 8 节。
- 第 5 节不写搜索量、难度或排名预测，除非有带来源和日期的数据。全文不写行业基准数字。
- 没做落地模块时，第 4 节里"线索由谁跟进"写"本次未做"，不推测。

## 通用默认模式

读不到细分包时用。按主转化动作判断网站属于哪一种：

| 类型 | 主要任务 | 主转化动作 | 常见页面 |
|---|---|---|---|
| 展示型 | 让来访的人确认这家企业可信、做得了这件事 | 打电话或留言 | 首页、业务或产品、案例与证明、关于、联系 |
| 询盘型 | 让合适的客户留下一条信息完整的需求 | 提交询盘或需求表单 | 首页、产品或方案详情、能力与资质、案例、合作流程、联系与询盘 |
| 成交型 | 让顾客看懂、放心并完成下单 | 加入购物车并付款 | 首页、分类、商品详情、评价、配送与退换、常见问题、联系与售后 |

拿不准属于哪一种时，问客户一句："访客最后应该做的那一个动作是什么？"
