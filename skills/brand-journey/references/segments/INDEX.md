# 细分包登记表

通用主线每个客户都走。细分包只在主线之上补充这一类客户特有的问题、证明和网站模式。一个细分包就是本目录下的一个文件，在下表登记后才生效。

| segment | 名称 | 识别信号摘要 | file |
|---|---|---|---|
| export-b2b | 外贸 B2B | 卖给海外企业买家；谈起订量、交期、贸易条款；靠询盘成交 | export-b2b.md |
| domestic-b2b | 国内 B2B | 卖给国内企业或机构；方案报价、合同与账期；靠线索和销售跟进成交 | domestic-b2b.md |
| dtc-ecommerce | DTC 电商 | 自有品牌直接卖给消费者；零售定价、运费、退换；在线下单成交 | dtc-ecommerce.md |

## 选择规则

1. 阶段 0 读完现有资料后，对照各包第 1 节的识别信号判断。以"钱从谁那里来、怎样成交"为准，命中信号最多的那一类优先。
2. 告诉操作者判定为哪一类、依据是哪几条信号。操作者确认或改正之后，才把标识写进 `BRAND.md` 文件头的 `segment` 和 `PROGRESS.md`。
3. 判定之前，`segment` 保持 `unknown`。
4. 哪一类都不像时用 `generic`：不加载任何细分包，只走通用主线。通用主线必须能独立跑完。不要为了套上细分包而勉强归类。
5. 混合客户（例如既做出口批发又有国内零售）：先问这次工作主要服务哪一类生意，把它定为主细分包。第二个细分包只在可选模块 E1、E2、W1 补充加问，不参与必选主线。把它记在 `PROGRESS.md` 阶段 0 一行的备注里，写作"第二细分包：标识"，例如"第二细分包：dtc-ecommerce"；续接时据此加载。两类客户的事实、证明和承诺分开记，不揉成一个万能定位。
6. 个人与创始人品牌用 `$brand-foundation` 的个人分支，可以叠加在任何细分之上。

`generic` 和 `unknown` 是保留标识，不能登记成细分包。

## 细分包怎样被使用

| 包内小节 | 谁在用 |
|---|---|
| 1 识别信号 | 阶段 0 判断客户类型 |
| 2 各阶段加问 | 对应阶段在通用问题之后追加；仍受每阶段必答上限约束 |
| 3 价格模块、4 渠道模块 | 落地模块 E1、E2；没选落地模块时不用 |
| 5 证明与高风险说法 | 阶段 5，以及任何要公开使用的说法 |
| 6 网站交接模式 | 建站模块 W1 和 `$brand-handoff`；没选建站模块时不用 |
| 7 表达注意 | 阶段 6 和 `$brand-expression` |
| 8 问卷加问 | 拼进发给客户的问卷，按"核心、落地、建站"三组取用 |

## 新增一个细分包

1. 在本目录加一个文件，文件名是 `<标识>.md`，标识用小写字母、数字和连字符。
2. 文件里恰好八个二级标题，写法和顺序与现有包相同；第 8 节下恰好三个三级标题：核心、落地、建站。
3. 在上表加一行。
4. 运行 `python3 scripts/validate_skills.py .`。

细分包里不写行业基准数字。转化率、获客成本、客单价之类只能来自客户自己的数据，或带来源和日期的研究。
