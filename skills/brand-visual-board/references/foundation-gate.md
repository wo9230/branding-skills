# 基础门禁

视觉选择会把模糊策略和候选文案变得“像真的”。先判断 `BRAND.md` 与可选 `MESSAGING.md` 是否足够支撑本次用途。

## Committed 模式最低条件

以下内容需要在 `BRAND.md` 中获批，或由用户明确指定某个 working 版本作为本轮依据：

- 当前品牌对象和本次视觉板服务的产品/业务；
- 优先受众及其使用或购买情境；
- 工作定位、关键取舍和不能传达的误解；
- 本次主要触点：网站、App、社媒、包装、空间、演示文稿等；
- 必须保留、必须避免及权限已知的现有资产；
- 语言、市场、技术、生产和可访问性约束。

如果板中展示标题、口号、产品说明、CTA 或其他承重文案，它们还需要在 `MESSAGING.md` 中获批，或由用户明确指定某个 working 版本用于本轮。没有 `MESSAGING.md` 时，只能使用 `BRAND.md` 中已经批准的最小信息；其余全部原位标为概念内容。

仅看到 `record_status: approved` 或 `message_status: approved` 不算通过。分别核对批准范围、批准人、日期和本次实际使用的承重内容。旧文件缺少这些字段时视为 working，除非有权限的用户在本轮明确指定该版本用于视觉开发。

事实证据未齐不必阻止所有视觉工作。例如案例不足不会阻止排版探索，但禁止在板中制造案例。会让方向完全改变的缺口才阻塞。

## Concept-exploration 模式

当 foundation 不完整但用户明确要脑暴时：

- 板首、每个 mock frame 和聊天摘要都标 `CONCEPT — NOT APPROVED`；
- 列出本轮采用的最少假设以及它们改变后会影响什么；
- 不写入 `BRAND.md` 的 approved 区；
- 推荐只能称“基于当前假设的领先方向”；
- 下一步是确认策略缺口或进行真实应用测试，不是直接生产 Logo、包装或网站。

如果只有名称与情绪形容词，且品类、受众和主要触点都未知，选择最可能改变方向的一个变量，每轮只问一个原子问题。例如先问“这个品牌现在实际提供什么？”；得到回答后再判断下一轮是否需要问受众或触点。不得用并列短语、多个问号或补充清单把多个缺口包装成一题。用户坚持立即探索时，限制为名称联想和可逆 mood study。

## 返回基础 Skill 的条件

遇到以下情况，停止视觉推演并列出需要 `brand-foundation` 解决的决定：

- 个人、公司或产品品牌关系不清；
- 多个受众需要相反的信任信号；
- 定位候选尚未选择且会导致完全不同的风格；
- 希望视觉暗示并不存在的高端、环保、技术、传统或性能证据；
- 现有 Logo、图片、字体或客户标志的权利不明；
- 用户要求视觉 Skill 替其决定业务、命名或公开承诺。

视觉 Skill 可以指出冲突，但不能反向修改战略事实。

定位、受众、供给、证明或承诺不清时返回 `$brand-foundation`；事实足够但标题、口号、简介、叙事或 CTA 尚未解决时返回 `$brand-expression`。
