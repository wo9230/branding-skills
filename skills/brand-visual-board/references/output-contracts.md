# 视觉交付协议

只有用户明确要求创建、保存、更新、写入或导出文件时才允许落盘；目标目录、附件或读取/审计/评审请求都不构成写入授权。确认写入意图后再解析用户的品牌项目根目录；本文件中的 `output/...` 均相对该目录。路径不明确时在聊天中交付，不猜测目录。禁止把产物写入或反向修改已安装 Skill。所有文件必须写明 foundation 文件、版本、读取日期、模式和批准状态；使用 `MESSAGING.md` 时也记录其文件、版本、读取日期和批准状态。视觉产物不成为新的品牌事实源或表达真源。

## 来源状态继承

视觉说明、比较表、摘要与 HTML 文字必须保留 foundation 和 messaging 的状态，不能统一写成 `[事实]`。使用用户语言的明确标签：

- `verified` → `[已验证事实]`；
- `user-stated` → `[用户自述]`；
- approved choice → `[已批准决策]`；
- `candidate` → `[候选决策]`；
- `hypothesis` → `[假设]`；
- `unknown/conflicted/stale` → `[未知]/[冲突]/[可能过期]`；
- 视觉 Skill 自己的比较和推荐 → `[视觉推断]` 或 `[视觉建议]`。

公开文案来自 `MESSAGING.md` 时，画面中不需要显示内部标签，但 `brand-system.md` 必须通过 Copy ID 或相邻说明保留其来源和放行范围。working/candidate 文案出现在画面时仍应原位标为概念内容。

不要把“foundation 已批准”理解为其中每条现实主张都已验证。若板面空间不足以逐条加标签，使用就近图例并让每条内容可明确映射；`brand-system.md` 中仍须逐条保留状态。

## `output/brand-system.md`

按本次任务保留必要部分：

1. **状态与依据**：`committed` 或 `concept-exploration`，引用的 `BRAND.md` 和可选 `MESSAGING.md` 版本、批准范围、未解决缺口；
2. **设计问题**：本次要解决的张力、主要触点和不能造成的误读；
3. **方向比较**：每个方向的战略关联、视觉原则、触点表现、维护成本、风险和待验证项；
4. **推荐与决策**：选择理由、候选/批准状态、批准人和适用范围；
5. **视觉语言**：角色化颜色、字体、版式、图像、图形、图标、材质和动效；
6. **表达示例**：优先使用已批准 Copy ID；模拟或候选内容原位标记；
7. **实施与验证**：字体和素材权利、对比度、语言覆盖、印刷/屏幕限制、需要真实测试的触点；
8. **禁止项**：容易滑向的套路、不能暗示的主张和不应复制的参考特征。

不要为每个项目机械填满所有设计类别。没有用途的设计变量、动效或包装规范不生成。

## `output/brand-board.html`

使用 [../assets/brand-board-template.html](../assets/brand-board-template.html) 作为结构起点，而非固定视觉风格。最终文件应：

- 单文件可打开，CSS 内嵌；默认不依赖构建工具；
- 把 `<html lang>` 更新为板内主要语言，把 `<title>` 更新为实际品牌与状态；不得保留模板值；
- 板首显示品牌、模式、版本和批准状态；
- 使用 `MESSAGING.md` 时显示 messaging 版本和状态；
- 以视觉呈现为主，避免把 Markdown 报告重新排版成网页；
- 探索时公平呈现 2–3 个实质不同方向；已有批准方向时专注深化；
- 默认不预选赢家；只有比较记录中存在可追溯推荐依据时才使用 selected/leading 状态；
- 展示真实的字体层级、颜色角色、图像原则和至少两个相关触点画面；
- 概念文字、产品、数字、人物、Logo 和界面在出现位置标 `Concept content`；
- 包含“已验证／待验证／禁止推断”区域；
- 在桌面和手机宽度上保持可读，无横向滚动。

修改模板的布局、密度和组件，使其服务方向。只换 CSS 变量不算完成设计。

## `output/brand-variables.css`

仅在实际实现需要时创建，使用语义名称：

```css
:root {
  --color-surface: #ffffff;
  --color-text: #111111;
  --color-accent: #2457ff;
  --font-display: system-ui, sans-serif;
  --font-body: system-ui, sans-serif;
}
```

记录设计变量的适用范围。未经测试的值不要命名为 `accessible`、`production` 或 `approved`。

## 浏览器检查

至少检查：

- 约 1440×900 桌面视口；
- 约 390×844 手机视口；
- 首屏状态是否明显；
- 字体失败时 fallback 是否可读；
- 长品牌名和中英文混排是否溢出；
- 每个模拟网站/App 画框内部的标题、彩色 span、导航、按钮和表格是否被 `overflow: hidden` 截断；页面本身没有横向滚动不代表画框内部安全；
- 概念标签是否贴近虚构内容；
- 颜色对比声明是否有测量依据；
- 本地打开时是否缺资源或报错。

优先用整页截图实际查看，并同时检查页面 `scrollWidth`。渲染工具不可用时明确写“未完成视觉验收”，不要用静态 CSS 检查替代；有另一种安全、已提供的本地浏览器方式时尝试一次。

聊天交付只说明创建的文件、推荐状态、完成的检查和仍需外部核验的事项。
